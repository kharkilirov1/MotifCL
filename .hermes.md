# MotifCL — coder rules (Vulkan port work)

MotifCL is a C++17 tensor/training/inference library with OpenCL (legacy) and Vulkan (target) GPU backends. GPU: AMD RX 580 (Polaris, wave64), Windows, GCC (Strawberry) + Ninja.

## Build & test (the ONLY sanctioned commands)

- Build:  `cmake --build build/rx580-release --parallel 12`
- Test:   `ctest --test-dir build/rx580-release -R <regex> --output-on-failure --timeout 300`
- Vulkan tests: test_vulkan_backend, test_vulkan_train_step, test_vulkan_reversible, test_vulkan_memory_native, test_vulkan_runtime_standalone
- Shader rebuild: kernels/vulkan/*.comp are compiled OFFLINE by `python tools/gen_vulkan_spirv.py` into `src/runtime/vulkan_spirv_kernels.inc` (committed). NEVER edit the .inc by hand. glslc comes from Android NDK shader-tools; env `MOTIFCL_GLSLC` overrides.
- Do NOT create new build directories. Do NOT run cmake configure unless asked.

## Vulkan port protocol (docs/VULKAN_PORT_PROTOCOL.md — binding)

1. OpenCL-backed Tensor path is NOT a Vulkan port. No hidden OpenCL fallback in ported paths.
2. Every port slice needs an OpenCL-free witness (test that doesn't link OpenCL).
3. Op is Vulkan-native only with device-resident I/O (inputs/outputs live in Vulkan buffers; host roundtrip only at test upload/download boundary).
4. Parity witnesses MUST cross tile sizes: >=2 workgroups, >=2 K-tiles, non-multiple-of-16 shapes.

## RX 580 driver lessons (reports/port-lessons/vulkan-fast-path.md — binding)

- SPIR-V 1.0 target; GL_EXT_shader_8bit_storage works (byte-granular uint8 stores OK).
- Do NOT use legacy VK_MEMORY_PROPERTY_* constants from old code — they are off by one bit. Use spec-correct bits.
- Batch footgun: VulkanBuffer::upload during an open batch executes immediately while batched dispatches run at batch_end — never upload into buffers written by an open batch.
- Batch keepalive is mandatory: every buffer bound in dispatch_cached must go into the batch keepalive list (shared_ptr) cleared after fence wait — otherwise temporaries die before submit and read garbage.
- Buffer pool exists (power-of-two buckets); vkAllocateMemory per tensor is catastrophic on this driver.
- Submit+fence floor ~150-200 us per dispatch — batching matters more than kernel micro-tuning at small shapes.
- Timestamps: reset+write in same command buffer, TOP_OF_PIPE before / BOTTOM_OF_PIPE after, mask by timestampValidBits (RX 580: period 40ns, 64 valid bits).

## Style & discipline

- C++17, match surrounding code style exactly. Error checks via MCL_CHECK. No new deps.
- Kernels: follow existing kernels/vulkan/*.comp naming and layout conventions (e.g. mm_f32_nt_rb4.comp, *_subgroup.comp variants).
- Minimal diffs. No drive-by refactors. No comments explaining what changed.
- NEVER run git commit/push/reset. Working tree edits only.
- Report format at the end of every task: (1) files touched, (2) what you ran and its ACTUAL output tail, (3) what is NOT verified yet. Do not claim success without command output proving it.
